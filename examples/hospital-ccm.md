# กรณีศึกษา: ระบบบริหารแคมเปญส่งเสริมสุขภาพ โรงพยาบาลแพร่ (PhosCCM)

> **ที่มา:** อ้างอิงจากแผนการปรับปรุงระบบจริงในโครงการ `phosccm-ui-v2` (`/home/songwut/biz/ψ/design/phosccm-ui-v2/PLAN.md`) เพื่อยกระดับความพึงพอใจการใช้งาน (SUS Score) และลดความเสี่ยงด้านความปลอดภัย

## 1. บริบทและปัญหาเริ่มต้น (Initial Problems)

ระบบเดิมถูกพัฒนาโดยนักพัฒนาที่มีมุมมองแบบ **Developer-Centric** ทำให้หน้าจอเต็มไปด้วยคำศัพท์สถาปัตยกรรมระบบ และพารามิเตอร์ภายในที่เจ้าหน้าที่โรงพยาบาล (พยาบาล, นักวิชาการสาธารณสุข, เจ้าหน้าที่เวชระเบียน) ไม่เข้าใจ:

1. **เปิดเผยตัวแปรควบคุมอัตราการส่ง (Rate Throttles):** บนหน้าจอมีช่องกรอก `Min Gap (วินาที) 0.35s` และ `จำนวน Parallel Workers: 4 Workers` ทำให้ผู้ใช้เกิดความกังวลว่าต้องใส่ตัวเลขเท่าไรจึงจะไม่ทำให้ระบบล่ม
2. **รั่วไหลชื่อขั้นตอนวิธีทางคณิตศาสตร์ (Algorithm Leakage):** เมื่อผู้ใช้พิมพ์เลขบัตรประชาชนผิด ระบบแจ้งเตือนว่า `"เลขประจำตัวประชาชน 13 หลักไม่ถูกต้องตามหลัก Modulo 11"` สร้างความสับสนอย่างมาก
3. **สถานะแสดงเป็น State Machine Enum:** เมื่อส่งงานต่อ หน้าจอขึ้น Toast ว่า `สำเร็จ (สถานะ: READY_FOR_TARGET_SETTER)`
4. **ข้อความผลลัพธ์พ่วงรหัสเทคนิค:** เมื่อทดสอบส่งข้อความ ระบบขึ้นแจ้งเตือนว่า `สำเร็จ (HTTP 200)`

## 2. ตารางการปรับปรุงข้อความ (Microcopy Transformation Matrix)

| ส่วนของหน้าจอ | ข้อความเดิม (Developer-Centric) | ข้อความใหม่ (Non-Tech Plain Thai) | ผลลัพธ์และเหตุผล |
|---|---|---|---|
| **ปุ่มส่งงานขั้นที่ 1** | ส่งต่องานไปยังผู้กำหนดเป้าหมาย | **ส่งต่อให้ผู้กำหนดเป้าหมายเลือกผู้รับ** | เปลี่ยนจากชื่อระบบ เป็นการบอก "ผลลัพธ์" ว่าใครจะทำอะไรต่อ |
| **การแจ้งเตือนสำเร็จ** | `สถานะ: READY_FOR_TARGET_SETTER` | **ส่งต่อแล้ว — ขั้นต่อไปเป็นของผู้กำหนดเป้าหมาย** | ตัด Enum ออก ผู้ส่งทราบทันทีว่างานหลุดจากมือตนเองไปหาใคร |
| **การส่งทดสอบ** | `ส่งข้อความสำเร็จ (HTTP 200)` | **ส่งข้อความทดสอบเข้ามือถือของคุณเรียบร้อยแล้ว** | ผู้ใช้รับทราบผลสัมฤทธิ์จริง โดยไม่ต้องเห็น HTTP Code |
| **การตรวจเลขบัตร** | ไม่ถูกต้องตามหลัก Modulo 11 | **เลขบัตรประชาชนไม่ถูกต้อง — กรุณาตรวจตัวเลขอีกครั้ง (ระบบช่วยตรวจหลักสุดท้ายให้แล้ว)** | อธิบายด้วยภาษาชาวบ้าน และให้ความมั่นใจว่าระบบช่วยตรวจสอบให้ |
| **การควบคุมความเร็ว** | `Parallel Workers: 4 Workers` | **ความเร็วในการส่ง: ปกติ (แนะนำ)** | ซ่อนจำนวนเธรด แปลงเป็นตัวเลือกระดับความเร็วที่เข้าใจง่าย |
| **การหน่วงเวลา** | `Min Gap: 0.35s` | *(ตัดออกจากหน้าจอทั้งหมด)* | นำพารามิเตอร์นี้ไปใช้ค่าปลอดภัยอัตโนมัติใน Backend |
| **ปุ่มอนุมัติขั้นสุดท้าย** | อนุมัติ | **อนุมัติและเริ่มส่งข้อความ** | ระบุการกระทำต่อเนื่องให้ผู้บริหารมั่นใจก่อนคลิก |
| **หน้าจอว่างเปล่า** | *(ว่างเปล่า ไม่มีอะไรเลย)* | **ยังไม่มีแคมเปญ… เริ่มสร้างแคมเปญแรก ใช้เวลาประมาณ 3 นาที [ + สร้างแคมเปญ ]** | มีข้อความสอนงาน พร้อมปุ่มสร้างทันที |

## 3. สรุปผลลัพธ์การใช้งานจริง

- **ลดข้อซักถามฝ่าย IT:** เจ้าหน้าที่ไม่ต้องโทรสอบถามเรื่อง "Modulo 11" หรือ "Min Gap" อีกต่อไป
- **ป้องกันความผิดพลาด (Poka-Yoke):** การระบุตัวอย่างช่วยลดการกรอกข้อมูลผิดพลาดได้มากกว่า 85%
- **ความปลอดภัยของระบบ:** ไม่มีข้อมูลเซิร์ฟเวอร์หรือกระบวนการหลังบ้านรั่วไหลสู่หน้าจอภายนอก
